# API Documentation

Base URL: `http://localhost:3000`. All request and response bodies are JSON.

| Method | Path                                 | Purpose                            |
| ------ | ------------------------------------ | ---------------------------------- |
| POST   | `/accounts`                          | Create an account                  |
| GET    | `/accounts/{accountId}/balance`      | Get an account's balance           |
| POST   | `/accounts/{accountId}/transactions` | Add a credit or debit              |
| GET    | `/accounts/{accountId}/transactions` | Transaction history (paginated)    |
| POST   | `/transfers`                         | Transfer money between accounts    |
| GET    | `/health`                            | Liveness and database connectivity |

Transactions are immutable: there are no `PUT`, `PATCH` or `DELETE` routes for them.

## Conventions

- **IDs** are UUIDs. A malformed ID returns `400`; a well-formed ID that does not exist returns `404`.
- **Money** (`amount`, `balance`, `balance_after`) is returned as a decimal **string** with two
  decimal places, e.g. `"150.00"`, so no precision is lost to floating point. Requests may send
  `amount` as a JSON number (`100`, `10.5`) or a string (`"10.50"`).
- **Timestamps** are ISO 8601 in UTC, generated by the server.
- **Unknown fields** in request bodies are rejected with `400`. This is how a client-supplied
  `balance` on account creation is refused.

## Errors

Every error has the same shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [{ "field": "amount", "message": "amount must be greater than 0" }]
  }
}
```

`details` is present only when there is something useful to add.

| Status | `code`                  | When                                                                        |
| ------ | ----------------------- | --------------------------------------------------------------------------- |
| 400    | `VALIDATION_ERROR`      | Missing or invalid field, bad type or amount, bad pagination, unknown field |
| 400    | `INVALID_JSON`          | The request body is not valid JSON                                          |
| 404    | `ACCOUNT_NOT_FOUND`     | The account (or either transfer account) does not exist                     |
| 404    | `NOT_FOUND`             | Unknown route                                                               |
| 409    | `DUPLICATE_TRANSACTION` | `reference_id` was already used on this account                             |
| 422    | `INSUFFICIENT_BALANCE`  | A debit or transfer would make the balance negative                         |
| 500    | `INTERNAL_ERROR`        | Unexpected server error (details are logged, not returned)                  |

## POST /accounts

Creates an account. `id`, `balance` (always `0`) and `created_at` are set by the server.

**Body**

| Field  | Type   | Rules                          |
| ------ | ------ | ------------------------------ |
| `name` | string | Required, 1–100 chars, trimmed |

```bash
curl -X POST localhost:3000/accounts \
  -H 'Content-Type: application/json' \
  -d '{"name": "Alice"}'
```

**201 Created**

```json
{
  "id": "e210bb6e-ba04-4942-ad4e-3af0378e3bf5",
  "name": "Alice",
  "balance": "0.00",
  "created_at": "2026-10-26T15:01:21.646Z"
}
```

**Errors:** `400 VALIDATION_ERROR` (missing or blank `name`, or any extra field such as `balance`),
`400 INVALID_JSON`.

## GET /accounts/{accountId}/balance

```bash
curl localhost:3000/accounts/e210bb6e-ba04-4942-ad4e-3af0378e3bf5/balance
```

**200 OK**

```json
{ "account_id": "e210bb6e-ba04-4942-ad4e-3af0378e3bf5", "balance": "70.00" }
```

**Errors:** `400 VALIDATION_ERROR` (malformed ID), `404 ACCOUNT_NOT_FOUND`.

## POST /accounts/{accountId}/transactions

Adds a credit (increases the balance) or a debit (decreases it). Writing the transaction and
updating the balance happen in one database transaction.

**Body**

| Field          | Type             | Rules                                                        |
| -------------- | ---------------- | ------------------------------------------------------------ |
| `type`         | string           | Required, `"credit"` or `"debit"`                            |
| `amount`       | number or string | Required, > 0, at most 2 decimal places, < 1,000,000,000,000 |
| `reference_id` | string           | Required, 1–100 chars, unique per account                    |
| `description`  | string           | Optional, at most 255 chars                                  |

```bash
curl -X POST localhost:3000/accounts/e210bb6e-ba04-4942-ad4e-3af0378e3bf5/transactions \
  -H 'Content-Type: application/json' \
  -d '{"type": "credit", "amount": 100, "reference_id": "salary-2026-10", "description": "Salary"}'
```

**201 Created**

```json
{
  "id": "4a1d8f0e-2c0b-4f7e-9d65-1f2a3b4c5d6e",
  "account_id": "e210bb6e-ba04-4942-ad4e-3af0378e3bf5",
  "type": "credit",
  "amount": "100.00",
  "balance_after": "100.00",
  "description": "Salary",
  "reference_id": "salary-2026-10",
  "transfer_id": null,
  "created_at": "2026-10-26T15:01:21.700Z"
}
```

`balance_after` is the account balance right after this transaction. `transfer_id` links the two
legs of a transfer and is `null` otherwise.

**Errors**

- `400 VALIDATION_ERROR`: invalid `type`, `amount` ≤ 0, too many decimals, missing `reference_id`, …
- `404 ACCOUNT_NOT_FOUND`
- `409 DUPLICATE_TRANSACTION`: the `reference_id` already exists **for this account**. Nothing is
  created and the balance does not change. The existing transaction is returned in
  `details.transaction`, so a client retrying after a timeout can see the original result.
  The same `reference_id` is allowed on different accounts.
- `422 INSUFFICIENT_BALANCE`: the debit is larger than the balance. Nothing is created.

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance for this debit",
    "details": { "account_id": "e210…", "balance": "100.00", "requested_amount": "150" }
  }
}
```

## GET /accounts/{accountId}/transactions

Returns transactions latest first (by `created_at`).

**Query parameters**

| Param   | Default | Rules                                         |
| ------- | ------- | --------------------------------------------- |
| `type`  | (none)  | `credit` or `debit`; leave it out to get both |
| `page`  | `1`     | Integer ≥ 1                                   |
| `limit` | `20`    | Integer 1–100                                 |

```bash
curl 'localhost:3000/accounts/e210bb6e-ba04-4942-ad4e-3af0378e3bf5/transactions?type=debit&page=1&limit=10'
```

**200 OK**

```json
{
  "data": [
    {
      "id": "ea84b388-84b2-468f-9764-18067f7eab17",
      "account_id": "e210bb6e-ba04-4942-ad4e-3af0378e3bf5",
      "type": "debit",
      "amount": "30.00",
      "balance_after": "70.00",
      "description": "Transfer to af40aaed-36e9-48ed-920d-683b9791db2d",
      "reference_id": "t1",
      "transfer_id": "5c93fc8a-0c69-4417-a305-cba152887623",
      "created_at": "2026-10-26T15:01:21.824Z"
    }
  ],
  "pagination": { "page": 1, "limit": 10, "total_records": 1, "total_pages": 1 }
}
```

A page past the end returns `200` with an empty `data` array.

**Errors:** `400 VALIDATION_ERROR` (e.g. `page=0`, `limit=500`, `type=refund`), `404 ACCOUNT_NOT_FOUND`.

## POST /transfers (bonus)

Moves money from one account to another. The debit from the source and the credit to the
destination are written in one database transaction; if any part fails, nothing is written.
Both legs appear in each account's history with the same `transfer_id` and `reference_id`.

**Body**

| Field             | Type             | Rules                                         |
| ----------------- | ---------------- | --------------------------------------------- |
| `from_account_id` | UUID             | Required, must exist                          |
| `to_account_id`   | UUID             | Required, must exist, different from source   |
| `amount`          | number or string | Same rules as transactions                    |
| `reference_id`    | string           | Required; must be unused on **both** accounts |
| `description`     | string           | Optional; defaults to "Transfer to/from …"    |

```bash
curl -X POST localhost:3000/transfers \
  -H 'Content-Type: application/json' \
  -d '{"from_account_id": "<A>", "to_account_id": "<B>", "amount": 30, "reference_id": "t1"}'
```

**201 Created**

```json
{
  "transfer_id": "5c93fc8a-0c69-4417-a305-cba152887623",
  "from_account_id": "<A>",
  "to_account_id": "<B>",
  "amount": "30.00",
  "reference_id": "t1",
  "created_at": "2026-10-26T15:01:21.824Z",
  "debit_transaction": { "...": "transaction on A, balance_after 70.00" },
  "credit_transaction": { "...": "transaction on B, balance_after 80.00" }
}
```

**Errors:** `400 VALIDATION_ERROR` (including same source and destination),
`404 ACCOUNT_NOT_FOUND` (either account), `409 DUPLICATE_TRANSACTION`, `422 INSUFFICIENT_BALANCE`.

## GET /health

Returns `200 {"status":"ok"}` when the API can reach the database. Used by the Docker health check.
